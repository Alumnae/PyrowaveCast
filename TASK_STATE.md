# Project State

## Current architecture
macOS/iOS Server -> SPPW/1 (proprietary UDP, 40-byte header, no checksum (`payloadChecksum` always 0), optional encryption (X25519/Ed25519 handshake, AES-256-GCM per datagram, CPace pairing with 5-digit PIN or headless password), Bonjour `_pyrowave._udp`) -> macOS/iOS Receiver.
Bitstream: vendored upstream PyroWave encoder (`Vendor/pyrowave-metal`), bitstream format unchanged. Only local vendor patch: `wrap_gpu_input` accepts a full resolution biplanar surface (`'444f'` / `'xf44'`) for a 4:4:4 encoder.
Chroma: 4:2:0 by default; macOS server optional 4:4:4 (`'xf44'` capture → PyroWave 4:4:4 → receivers decode to BGRA). iOS server stays 4:2:0.

### Native SPPW/1 Transport & Media Pipeline
- **ScreenCaptureKit & ReplayKit capture**: macOS `ScreenCaptureEngine` (`SCStream` `.screen` + `.audio` @ 48 kHz stereo) with actor-reentrancy protection and zero-copy `IOSurface`-backed `CVPixelBuffer` transfer to `UpstreamMetalEncoder`; iOS `IOSScreenOutput` / `RPScreenRecorder`.
- **Asymmetric LL/HF Reed-Solomon ECC (FEC)**: Systematic Cauchy Reed-Solomon over $\text{GF}(2^8)$ (`SPPWReedSolomonGF256`, wire message `kind = 8` `.fecParity` with 8-byte `SPPWFECBlockHeader`). `SPPWPyrowaveSubbandInspector` locates the exact byte boundary of the coarse LL subband (`level == 4, band == 0` across Y/Cb/Cr) so LL fragments are tagged (`SPPWFragmentFlags.llCritical`) and receive $2\times$ parity protection (minimum 25%, $\ge 2$ parity shards) while HF detail fragments are protected in blocks of up to 48 shards.
- **Low-latency LL-drop & Partial-HF GPU decode**: `SPPWFrameAssembler` immediately drops any older incomplete frame missing unrecoverable LL packets (`llDroppedFrames`) instead of stalling on a dead frame. When LL is 100% intact and only trailing HF detail packets are lost, it salvages the valid block-aligned prefix (`isPartialHF = true`) and `PyrowaveDecoderSession.decode(_:allowPartialFrame:)` reconstructs the frame on Metal with zeroed missing HF coefficients.
- **Packet pacing, Socket buffers (`SO_SNDBUF`/`SO_RCVBUF`) & Wi-Fi jitter buffer**: POSIX dual-stack UDP sockets (`SPPWUDPServerSocket`, `SPPWUDPClientSocket`) with explicit `SO_SNDBUF`/`SO_RCVBUF` (4 MB on macOS, 2 MB on iOS with progressive fallback) and DSCP CS4 (`0x80`, WMM `AC_VI`), sub-millisecond `mach_wait_until` micro-burst pacing (`SPPWMediaPacer` with newer-frame preemption), and RFC 3550 EWMA adaptive Wi-Fi buffer (`SPPWAdaptiveWiFiBuffer`).
- **Closed-Loop Adaptive Bitrate (ABR)**: `SPPWAdaptiveBitrateController` (`Sendable`) active when `automaticBitrate == true`. Evaluates network health every **1 second** and steps bitrate down each second while packet loss (LL drop, frame expiration, late decode drop), partial-HF fallback, high FEC recovery, or Wi-Fi jitter persist until the link stabilizes. Ramp-up requires at least **5 seconds** of continuous clean link (`minimumRampUpCooldownNanoseconds = 5s`, same interval as WebRTC GCC probes) with backoff after a failed probe (`20s`, then `40s`). If probing higher bitrate re-triggers link instability, it reverts immediately to the last problem-free bitrate (`.revertToStable`), and locks the safe ceiling (`isCeilingLocked = true`) if instability persists (`failedProbeCount >= 2`), released after 30 s clean, eliminating bitrate oscillation on penalized networks. Both macOS `StreamServer` and iOS `IOSStreamServer` honor the dynamic receiver `maxBitrate` budget without interrupting capture (`flags == 0`).
- **Client-chosen resolution**: `SPPWResolutionLadder` (short-side levels 2160/1440/1080/720/480/360/320 derived from the server's aspect, never upscaled; wire `0×0` native, `0×S` short side, `W×H` legacy fit), `SPPWResolutionMode` (Nativa / Automatica / level) in both receivers, `SPPWAutoResolutionController` (client-side, driven by the adaptive bitrate). macOS server scales via ScreenCaptureKit, iOS server via `IOSFrameScaler` (`VTPixelTransferSession`).
- **Background / keep-awake**: `SPPWStreamingActivity` (process activity: no App Nap, `latencyCritical`, no idle sleep; no display sleep while capturing the screen or watching) held by the macOS server while running and by receivers while connected. macOS server restarts a capture source that stopped on its own (display sleep/lock, system interruption) with backoff (`SPPWSourceRestartPolicy`) while clients are connected. iOS: `IOSKeepAwake` disables auto-lock while server or receiver are active, `IOSBackgroundStreamingGuard` requests background time and logs it; `UIBackgroundModes` includes `audio`.
- **A/V sync**: both servers stamp video and audio with the capture instant (`SPPWCaptureClock`, host clock); receivers align audio to the measured video delay (`SPPWAVSyncClock` + jitter buffer `SPPWAudioJitterController`, sequence-ordered playout); servers send audio through `SPPWOrderedPacketQueue`. iOS server sends audio in screen capture mode (SCK `.audio` on iOS 27, ReplayKit `.audioApp` fallback; resampled with `AVAudioConverter`).
- **Server audio sources & volume**: `SPPWAudioSourceCatalog` (none / system / input devices from the system), `SPPWMicrophoneCapture` (iOS `AVAudioEngine`), macOS microphones via ScreenCaptureKit (macOS 15+), `SPPWAudioPacketizer.gain` (0–2, live). Video file mode streams the file audio through an `MTAudioProcessingTap` (`TestVideoAudioTapContext`).
- **Remote control (iOS receiver → macOS server)**: wire events `text` (committed Unicode, IME-safe, `CGEventKeyboardSetUnicodeString`), `keyPress` (atomic key code + modifiers), `pointerDelta` / `buttonAtCursor` / `clickAtCursor` (trackpad), `sequenced` envelope (sent twice, `SPPWInputSequenceFilter` per client). Helpers in `SPPWCommon`: `SPPWMacKeyCode` (HID→kVK, ANSI char map), `SPPWStickyModifiers`, `SPPWKeyboardTranslator`, `SPPWSpecialKey`, `SPPWPointerAcceleration`. Clipboard sync `kind = 10` (`SPPWClipboardChannel`, chunks + ack + retransmit, digest anti-echo; `SPPWMacPasteboardBridge` on the server, `IOSClipboardSession` / `IOSClipboardBridge` with `localOnly` writes and `UIPasteControl` reads on iOS). iOS model support is in `IOSReceiverModel` (settings, `sendTypedText`, `sendSpecialKey`, `sendHardwareKey`, `sendClipboardToHost`).
- **Audio & Input channels**: `SPPWAudioPacketizer` + `SPPWAudioPlayer` (`AVAudioEngine` low-latency PCM16 48 kHz stereo with automatic 3 s idle pause, wire `kind = 9` `.audioFrame`) and `SPPWInputEvent` + `SPPWMacInputInjector` (`CGEvent` mouse/scroll/keyboard/touch injection, wire `kind = 4` `.input`).
- **Build & Version Display**: `SPPWBuildVersion` displays formatted version strings including short git commit hash (e.g. `v0.6.4 (build 604, 7fd7479)`).

## Shared decisions
- **Nessun percorso locale nei binari macOS (2026-11-25):** `build-app.sh`, `build-gui.sh` e `build-receiver.sh` eseguono `strip -S -x` sull'eseguibile prima della firma ad hoc: i simboli di debug elencano ogni file oggetto con il percorso assoluto di build (cartella home dell'utente). Il binario passa da ~7,7 MB a ~3,6 MB. La build 0.6.18 esistente è stata ripulita e rifirmata ad hoc.
- **Log console in inglese (2026-11-25):** tutti i messaggi di log (server, ricevitore, sicurezza, estensione) sono solo in inglese, su ogni dispositivo e lingua dell'app. Per le chiavi condivise con l'interfaccia usare `SPPWLocalization.english(_:)` (e `SPPWResolutionMode.englishTitle`); il testo a schermo resta tradotto con `SPPWLocalization.tr`. Niente stringhe di log hard-coded in italiano.
- Native Apple APIs; keep `SPPW/1` (NativeMode) and the PyroWave bitstream format intact (MIT).
- **TimeMachine Local Snapshots:** Every agent must execute `./scripts/snapshot.sh "<Agent Role>: <summary>"` (or `git snapshot "<summary>"`) at the end of its turn to record an immutable local recovery checkpoint before ending.
- **Versioning & Regola di Build (incremento Z):** Shared `VERSION`. **REGOLA:** Ogni volta che si esegue una build, la cifra **Z** di `X.Y.Z` (patch) **DEVE essere incrementata** (`--patch` $\to$ `X.Y.(Z+1)`). Ogni ciclo o esecuzione di build deve avanzare Z per garantire versioni progressive e tracciabili.
- **Adaptive Bitrate (ABR):** Ceiling calculated via `width * height * 1.4 * quality * fps` quantized to 1 Mb/s. When `automaticBitrate == true`, receivers adjust runtime target in 1s ticks without overwriting user manual `bitrateMbps` setting. Servers enforce `min(autoBudget, maxBitrateCap)` and apply `.streamConfiguration` updates seamlessly without restarting capture (`flags == 0`).
- **Punktfunk: DEFERRED** — proprietary QUIC stack (`_punktfunk._udp`), no public spec/license; revisit only with official spec/permission (no decompilation).
- **Moonlight/Sunshine: DEFERRED** — clean-room MIT only (never copy GPLv3 code), behind `StreamSessionProvider`, only if a PyroWave-capable client is verified.
- **Steam Remote Play: EXCLUDED** — closed protocol/client, SSA restricts reverse engineering.
